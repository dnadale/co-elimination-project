# Session summary, 2026-10-21

Audit of the project plus fixes to the phylogenetic validation. Scripts and outputs listed below are all in the repo;
`ENVIRONMENT.txt` and `requirements.lock.txt` record versions, hashes and seeds. Run order is in `run_all_analysis.sh`.

## Verified (src/audit_checks.py -> results/audit/)
- All 162 raw TOGA status files match the SHA-256 in `download_manifest.tsv`; tree, roster and TOGA catalog match the assembly manifest.
- Rebuilding the matrix from the raw files gives a table identical to `analysis/gene_status_matrix.tsv` (19,464 genes x 162 species).
- Status report numbers reproduce: 74.7% I, 4.5% L, 4.5% UL; CIROZ lost in 91 species; LR Fisher ORs and p-values; 7,389,576 pairs pass the screen thresholds.
- Genomes, alignments and ortholog files were never needed: the pipeline starts from TOGA's precomputed human-reference gene status.

## Problems found
1. **"The blind screen recovered CIROZ" is overstated.** LR module pairs rank 1,241 to 162,185 of 7,389,576 by raw excess
   (`results/audit/lr_module_rank_in_screen.tsv`). CIROZ only reaches the top 100 through MCTS2, because raw excess favors genes lost in many species.
   The Fisher tests on known genes are valid; they show the data contain the signal, not that the screen finds it.
2. **Assembly quality leaks into calls** (`results/audit/status_vs_assembly_quality.tsv`): PM vs scaffold N50 rho = -0.92, M vs contig N50 rho = -0.61,
   L vs contig N50 rho = -0.21. `Tupaia_chinensis` (contig N50 ~3 kb, 2,452 intact genes, 5,036 UL) should be excluded or flagged (not done).
3. **Human-reference bias:** primates have the fewest L calls because they are closest to human; clade-clustered losses count as few independent events.
4. `Canis_lupus` / `Canis_lupus_familiaris` and two `Ceratotherium_simum` tips are near-duplicates counted as separate species.
5. **The first tree null was miscalibrated:** simulated loss frequency differed from observed (e.g. MCTS2 19% vs 59%).
6. **Pagel LRTs were unstable** in the first top-100 run (independent model stuck in local optima; top-10 rerun differed by up to 29.5 LRT).

## Fixes
- `src/phylo_null_coloss.py`: simulations are kept only if the gene's simulated loss count is within 10% (min 2) of observed; 100,000 simulations;
  `PI` treated as ambiguous like the screen; gene symbol "NA" no longer read as missing; branch lengths scaled by lineage loss burden (`BURDEN_AWARE=0` disables).
  Previous version without burden scaling: `results/phylo_null/phylo_null_pairs_conditioned_no_burden.tsv`.
- `src/phylogenetic_candidate_test.py`: random optimizer starts plus a warm start of the dependent model from the independent fit (nested models).
  Re-run on the 19 unlinked pairs (`src/run_pagel_unlinked_parallel.sh`, `src/merge_pagel_chunks.py`): 15/19 LRTs unchanged (4 moved by 0.4 to 2.3), all optimizers converged, no negative LRTs.
- New: `src/matched_pair_null.py` (compare each pair with all gene pairs of matched loss counts), `src/make_candidate_triage.py` (combined table), `src/audit_checks.py`, `src/record_environment.py`.

Known limit: even with count conditioning and burden scaling, the independent-gene tree null still passes the block pairs and passes only 4/10 LR control pairs,
so it cannot separate real co-loss from gene-family blocks on its own. The matched-pair null does that job. All 10 LR pairs are extreme in the matched-pair null
(1 to 59 matched pairs at least as overlapping out of 29k-107k), which supports the positive control independently of the Fisher tests.
